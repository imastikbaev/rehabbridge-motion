# RehabBridge Motion

Браузерный прототип для сопровождения двигательных упражнений после инсульта. Камера отслеживает выбранную руку, приложение показывает подсказки и считает завершённые повторы.

[Репозиторий на GitHub](https://github.com/imastikbaev/rehabbridge-motion) · **[Открыть приложение](https://rehabbridge-motion-admit-2026.vercel.app/)** · [Демо на 2–3 минуты](docs/DEMO.md) · [Требования кейса](docs/REQUIREMENTS.md)

Проект подготовлен для Admit Motion 2026. Это демонстрация технического решения, не программа лечения: упражнения и допустимую нагрузку определяет специалист. Проверки на пациентах не проводились.

## Как это работает

1. Выберите руку и число повторов. Для короткой демонстрации достаточно одного повтора на задание.
2. Включите камеру. В кадре должны быть оба плеча, локоть и запястье выбранной руки.
3. После настройки оставьте руку у корпуса, кисть ниже плеч. Через три секунды практика начнётся автоматически.
4. Пройдите три задания. Повтор засчитывается после движения, удержания и возврата.
5. Между заданиями можно отдыхать без таймера. Согните и верните руку, чтобы продолжить.
6. Посмотрите результат. Повторить занятие можно тем же жестом или кнопкой.

Пауза и остановка доступны кнопками; на телефоне они закреплены внизу. При потере человека, устаревшем кадре или скрытии вкладки счёт останавливается. После восстановления нужно начать незавершённый повтор заново.

### Движения

| Задание | Что проверяет приложение |
| --- | --- |
| Сгибание локтя | Угол между плечом, локтем и запястьем, затем возврат |
| Рука в сторону | Боковое смещение относительно плеч при разогнутом локте |
| Раскрытие кисти | Четыре видимых раскрытых пальца, затем возврат кисти в исходное состояние |

Большой палец отдельно не оценивается. Порог сгибания и бокового смещения можно настроить перед занятием. Это параметры распознавания по изображению, а не клинические измерения.

### Подсказки и ошибки

Режим ошибок работает постоянно. Приложение сообщает, если рука не видна, движение не достигло отметки, локоть ушёл в сторону, пальцы перекрыты или в кадре несколько людей. Предупреждение показано крупным текстом с контрастной рамкой. Исчезновение руки не считается возвратом или повтором.

Звук включается отдельно. Один тон означает достижение отметки, два восходящих — зачёт повтора, три — старт. Два низких тона сообщают о паузе при потере распознавания. Для зачёта после отметки всё равно нужен возврат.

## Локальный запуск

Нужны Node.js 22.12 или новее, npm и браузер с камерой и WebAssembly.

```sh
npm ci
npm run assets
npm run dev
```

Откройте адрес, который напечатает Vite, обычно `http://127.0.0.1:5173`.

`assets` скачивает две официальные модели Google, проверяет SHA-256 и копирует WASM из установленного пакета MediaPipe. Первый запуск требует интернета. Файлы моделей не хранятся в Git.

На телефоне камера требует HTTPS. Адрес компьютера вида `http://192.168.…` для этого не подходит; используйте опубликованное приложение.

## Проверки и сборка

```sh
npm test
npx playwright install chromium
npm run test:e2e
npm run build
```

Для проверки production-сборки запустите preview:

```sh
npm run preview -- --port 4179 --strictPort
```

В другом терминале:

```sh
npm run check:production
```

Проверка публичного сайта:

```sh
CHECK_BASE_URL=https://rehabbridge-motion-admit-2026.vercel.app npm run check:production
```

Unit-тесты проверяют геометрию, удержания, счётчик, паузы, загрузку и освобождение ресурсов. Playwright проверяет сценарии интерфейса. Для тестов логики есть dev-страница `/?lab` с синтетическими координатами; в production она отключена. Искусственная камера и синтетические точки не заменяют проверку реальных движений. Подробности — в [отчёте о проверках](docs/VERIFICATION.md).

## Стек и устройство

React 19, TypeScript, Vite 7, MediaPipe Tasks Vision. Используются готовые Pose Landmarker Lite и Hand Landmarker. Собственная модель не обучалась.

Модели дают координаты тела и кистей. Правила в `movement.ts` нормализуют их относительно плеч с учётом пропорций кадра, сглаживают шум и проверяют полный цикл движения. Разные пороги входа и выхода уменьшают переключения около границы. Удержания требуют нескольких кадров; cooldown защищает от повторного срабатывания. Переходами между настройкой, практикой, отдыхом и результатом управляет `session.ts`.

Видео и рисунок скелета зеркалятся вместе. Левую и правую руку выбирают по стороне тела человека, а не по стороне экрана.

```text
src/
  main.tsx              Интерфейс и связь камеры со сценарием
  movement.ts           Геометрия, условия движений, счёт повторов
  session.ts            Этапы занятия, автозапуск, паузы
  camera.ts             MediaPipe и жизненный цикл камеры
  download.ts           Загрузка с прогрессом и отменой
  frame-health.ts       Контроль свежести кадров
  audio-feedback.ts     Звуковые сигналы
  history.ts            Локальные результаты
  ExerciseGuide.tsx     Инструкции к заданиям
  Illustration.tsx      Схемы движений
  fixtures.ts           Синтетические данные для тестов
  *.test.ts             Unit-тесты рядом с модулями
  style.css             Адаптивный интерфейс
scripts/                Подготовка моделей и проверка сборки
tests/                 Браузерные сценарии Playwright
docs/                  Требования, демо, проверки и деплой
public/                Генерируемые модели и WASM, вне Git
```

## Данные

Обработка идёт локально в браузере. Видео и координаты не записываются и не отправляются на сервер; микрофон не запрашивается. В localStorage остаются до десяти завершённых результатов: счётчики, цель по повторам и время активной практики, без имени и диагноза.

Backend и регистрация не нужны. Сеть используется для загрузки статических файлов. CSP разрешает соединения со своим доменом и локальными Blob, блокируя внешнюю телеметрию MediaPipe.

## Происхождение

**RehabBridge существовал до хакатона. Он не выдаётся за новую разработку.** Его код изучался как инженерный референс; исходные файлы и фрагменты кода из него не переносились, старый проект не изменялся.

В рамках хакатона заново реализованы правила движений, сценарий занятия, обработка ошибок, интерфейс и тесты. Часть технической основы сохранена из первого варианта «Орбита», созданного в этой же хакатонной сессии. Разработка велась с помощью Codex. Источники и изменения перечислены в [REUSE.md](REUSE.md), сторонние компоненты — в [THIRD_PARTY.md](THIRD_PARTY.md).

Git-репозиторий создан при подготовке к сдаче 30 сентября 2026 года. Первый коммит фиксирует уже подготовленный проект; он не является историей разработки за предыдущие дни. Даты коммитов не изменяются.

## Ограничения

- Распознавание зависит от освещения, ракурса, расстояния и видимости суставов и пальцев.
- Ограниченная амплитуда может не соответствовать текущим правилам. Нельзя увеличивать усилие ради счётчика.
- На слабых телефонах синхронная обработка моделей может тормозить. Первый запуск скачивает модели и WASM и зависит от сети.
- Проверки физических iPhone/Android и занятий с пациентами не проведены. Адаптивная вёрстка проверялась в Chromium с разными размерами экрана.
- Приложение не оценивает боль, безопасность упражнения или восстановление. Метрики старой Kinect-модели к веб-камере не применяются.
